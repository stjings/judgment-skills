# Evidence Review

**증거 게이트**와 **판단 게이트**를 통과시키는 스킬이다. "완료"라는 문장 대신 실제로 실행해 관찰한 결과로 다음 단계를 정한다. mattpocock의 `code-review`가 코드 diff를 Standards/Spec 두 축으로 보는 것이라면, 이 스킬은 **완료 기준 하나하나가 실제로 입증되었는가**를 본다.

먼저 Skill 도구로 `judgment-gates`를 호출해 증거 규칙을 읽는다. 호출할 수 없는 환경이면 이 문서만으로 진행한다.

## 1. 기준점을 잡는다

- **완료 기준의 출처**를 찾는다. 순서: 사용자가 준 경로나 티켓 → `docs/tasks/`의 브리프 → 이슈 트래커의 Acceptance criteria → 스펙 문서. 없으면 사용자에게 묻는다. 끝내 없다면 "완료 기준 없음"을 첫 번째 발견 사항으로 기록하고, 원래 요청에서 기준 후보를 뽑아 **(제안)**으로 표시한 뒤 진행한다.
- **원래 요구사항의 근거**(사용자가 처음 요청한 문장, 티켓 본문, 스펙)를 따로 확보한다. 브리프가 요청을 잘못 옮겼을 수도 있기 때문이다.
- git 저장소면 기준 커밋을 정하고 `git diff <기준>...HEAD`와 커밋 목록을 확보한다. 기준을 모르면 묻는다.

## 2. 기준마다 직접 확인한다

이전 보고서의 주장을 그대로 옮기지 않는다. 각 기준에 대해 지금 직접 실행할 수 있는 검증을 실행한다(테스트, 재현 스크립트, 요청 재현, 화면 확인). 실행할 수 없으면 왜 못 하는지 적는다.

결과를 이 표로 보여 준다.

| 완료 기준 | 바뀐 동작과 영향 범위 | 실제 실행한 검증 (환경) | 관찰 결과와 증거 위치 | 확인 못 한 범위와 남은 위험 | 판정 |
|---|---|---|---|---|---|

판정은 `통과`, `실패`, `부분`, `미검증` 중 하나다.

규칙:

- 요약이나 예상 결과를 실제 실행 결과처럼 쓰지 않는다. "이전 보고에서 통과했다고 함"은 증거가 아니다.
- 테스트 개수로 판정하지 않는다. 그 테스트가 기준을 실제로 다루는지 본다. 테스트가 구현을 따라 계산한 값을 기대값으로 쓰는(동어반복) 경우는 증거로 치지 않는다.
- 스크린샷은 화면 상태만 입증한다. 권한, 동시성, 데이터 무결성 기준에 스크린샷만 있으면 `부분`이다.
- 인증, 권한, 결제, 개인정보 기준은 실행 검증에 더해 관련 코드를 직접 읽고 판정한다.

## 3. 테스트가 놓치는 실패를 찾는다

기준 표와 별개로, 현재 테스트와 검증이 잡지 못하는 중요한 실패 상황을 찾는다. 웹 서비스라면 최소한 아래를 훑는다.

- 같은 요청의 중복·동시 실행 (더블 클릭, 재시도, 여러 탭)
- 날짜·시간 경계 (자정, 타임존, 월말, 이벤트 시작·종료 시각)
- 권한 없음, 세션 만료, 다른 사용자의 리소스 접근
- 외부 의존 실패 (API 타임아웃, 캐시 미스, DB 연결 실패)
- 대량 트래픽 시 쿼리·캐시 동작
- 로그와 응답에 개인정보나 비밀값 노출

각 항목에 "확인함 / 확인 안 함 / 해당 없음"과 근거를 단다.

## 4. 요구사항과 대조한다

1번에서 확보한 원래 요구사항과 실제 구현을 대조한다.

- **누락**: 요청했지만 구현되지 않았거나 일부만 된 동작
- **추가**: 요청하지 않았는데 들어간 동작 (범위 확장)
- **기준 변경**: 작업 중 완료 기준이 바뀐 흔적. 바뀌었다면 누가, 왜 바꿨는지 따로 표시한다. 기준을 낮춰 통과시킨 경우는 반드시 드러낸다.

git 저장소이고 `code-review` 스킬을 쓸 수 있으면, Skill 도구로 `code-review`를 호출해 Standards/Spec 검토를 돌리고 결과를 이 절에 그대로 붙인다(재정렬하지 않는다).

## 5. 사람이 설명할 수 있게 만든다

중요한 설계 선택 2~5개를 골라 사람이 자기 말로 설명할 수 있을 만큼 풀어 준다.

- 무엇을 선택했나
- 왜 (어떤 제약이나 의도 때문에)
- 고려할 수 있었던 대안과 버린 이유
- 이 선택이 틀렸을 때 나타날 증상

되돌리기 어렵고 이유가 필요한 선택이면 ADR로 남길지 묻는다.

## 6. 판단을 넘긴다

마지막에 한 블록으로 정리한다. 결정은 사람이 한다. 에이전트는 근거와 추천만 낸다.

```md
## 판단 요약
- 기준: 통과 N / 부분 N / 미검증 N / 실패 N
- 가장 큰 위험: <한 줄>
- 추천: 배포 가능 / 조건부 (무엇을 먼저 확인) / 보류
- 미룬 검토: <있으면 judgment-gates 형식으로. 인증·권한·결제·개인정보·운영 데이터는 미룰 수 없음>
```

저장소가 있고 미룬 검토가 있으면 `docs/deferred-reviews.md`에 추가할지 묻는다.

외부에 영향이 나가는 행동(배포, 발송, 운영 DB 쓰기, 원격 push)은 이 스킬이 실행하지 않는다.
