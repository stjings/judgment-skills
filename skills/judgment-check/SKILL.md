# Judgment Check

세션이나 하루 작업을 끝내기 전에 돌리는 짧은 점검이다. 점수를 매기는 용도가 아니라 **빠진 판단을 찾는 용도**다.

먼저 Skill 도구로 `judgment-gates`를 호출해 규칙을 읽는다. 호출할 수 없는 환경이면 이 문서만으로 진행한다.

## 1. 이번 세션을 훑는다

이번 대화(또는 사용자가 지정한 작업)에서 바뀐 것, 맡긴 것, 보고받은 것을 목록으로 정리한다. 저장소가 있으면 `git log`, `git status`, `docs/tasks/`, `docs/deferred-reviews.md`도 본다.

## 2. 여섯 가지를 확인한다

각 항목에 대해 에이전트가 근거를 찾아 `예 / 아니오 / 모름`으로 먼저 채우고, 사용자에게 확인받는다. 사용자가 직접 답해야 하는 항목(1, 6)은 질문으로 남긴다.

1. 누구를 위한 변경인지 내 말로 설명할 수 있다.
2. 이번에 하지 않을 일을 정해 뒀다.
3. AI가 대신 정한 중요한 가정과 선택을 알고 있다. → 이번 세션의 가정·선택을 실제로 나열해 보여 준다.
4. 완료 기준에 대응하는 실행 증거를 확인했다. → 증거 없이 "완료"로 넘어간 항목을 찾는다.
5. 확인하지 못한 범위와 그 영향을 알고 있다.
6. 결과에 이름을 걸 수 있거나, 남은 검토를 명시했다.

## 3. 상태를 짚는다

`judgment-gates`의 세 가지 상태 중 이번 세션에 보인 신호를 한두 줄로 알려 준다. 특히 **검증하지 않은 결과 위에 다음 작업을 쌓은 지점**(판단의 연기)이 있으면 구체적으로 짚는다. 훈계하지 않는다.

## 4. 정리한다

- `아니오`나 `모름`인 항목마다 다음 행동 하나를 제안한다: 지금 확인 / 미룬 검토로 기록 / 범위 축소.
- 미룬 검토는 `judgment-gates` 형식으로 정리하고, 저장소가 있으면 `docs/deferred-reviews.md`에 추가할지 묻는다.
- 같은 종류의 누락이 반복되면(예: 매번 동시성 검증이 빠짐) 문서 규칙보다 **강제 장치**(테스트 템플릿, CI 체크, hook)로 막는 쪽을 제안하고, mattpocock skills가 있으면 사용자에게 `/retro`를 권한다.

마지막으로 작게 시작하는 습관 하나를 고르게 한다.

- 작업 전 3줄: 목적, 제외 범위, 완료 기준을 먼저 적는다.
- 작업 후 1개: AI가 확인하지 못한 중요한 항목을 하나 찾는다.
- 검토가 밀리면: 동시 작업을 늘리기 전에 변경 단위와 검증 방법을 조정한다.
- 주기적으로: 유지하고 싶은 핵심 역량 하나는 AI 없이 직접 해 본다.
