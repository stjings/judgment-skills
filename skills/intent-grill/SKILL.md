# Intent Grill

mattpocock `grilling`의 인터뷰 방식으로 **의도 게이트**를 통과시킨다. 일반 grill이 "계획의 빈틈"을 찾는다면, 이 스킬은 거기에 더해 **사람이 확정한 기준**과 **AI가 혼자 정해도 되는 범위**를 남기는 데 집중한다.

먼저 Skill 도구로 `judgment-gates`를 호출해 규칙을 읽는다. 호출할 수 없는 환경이면 이 문서만으로 진행한다.

## 1. 이미 있는 것부터 읽는다

질문하기 전에 사용자가 이미 준 내용을 읽는다. 대화, 첨부 파일, 그리고 저장소가 있으면 `docs/intent.md`, `CLAUDE.md`/`AGENTS.md`, `GLOSSARY.md`, `docs/adr/`, `docs/agents/delegation.md`. 이미 답이 있는 질문은 하지 않는다.

**사실 확인은 에이전트의 일이고, 결정은 사람의 일이다.** 코드나 파일을 보면 알 수 있는 것은 직접 찾는다(가능하면 새 컨텍스트의 서브에이전트로). 사용자에게는 결정만 묻는다.

## 2. 의도 트리를 라운드로 채운다

아래 다섯 갈래가 의도 트리의 뿌리다. 결정은 다른 결정에 매달리므로, 선행 결정이 정해진 질문(**프런티어**)만 한 라운드에 묶어 묻는다. 아직 열린 질문에 답이 달린 질문은 다음 라운드로 넘긴다.

1. **대상과 문제**: 누구의 어떤 문제를 푸는가? 지금은 그 문제를 어떻게 견디고 있는가?
2. **목표와 제외 범위**: 이번에 달성할 것과 **이번에 하지 않을 일**. 제외 범위는 반드시 한 개 이상 받는다.
3. **판단 우선순위**: 속도, 단순함, 안정성, 비용, 사용자 경험이 충돌하면 무엇이 먼저인가? 순서로 받는다.
4. **위임 경계**: AI가 혼자 정해도 되는 선택과, 반드시 사람에게 물어야 하는 결정. `judgment-gates`의 기본 경계표를 보여 주고 이 프로젝트에 맞게 고칠 부분을 묻는다.
5. **성공의 모습**: 끝났을 때 무엇을 관찰하면 성공이라고 말할 수 있는가? (구체적 완료 기준은 `/delegate-task`에서 작업 단위로 다시 정한다.)

라운드 형식:

```
❓ **Q1** - **<질문 제목>**: <질문 본문. 필요하면 선택지 포함>

➡️ 추천: <추천 답과 한 줄 근거>

---

❓ **Q2** - ...
```

- "네"라고 답하면 추천안을 받아들이는 것이 되도록 질문을 쓴다.
- 답을 받으면 트리를 다시 계산하고 다음 라운드를 묻는다.
- 사용자가 "알아서 해"라고 하면 그 항목은 추천안으로 채우되 **미확정**으로 표시한다. 확정으로 바꾸지 않는다.

## 3. 충돌을 짚는다

답변이 기존 의도 문서, ADR, 앞 라운드의 답과 부딪히면 그 자리에서 짚는다. `judgment-gates`의 세 가지 선택(기존 유지 / 범위 안 절충 / 의도 변경)으로 묻는다. 충돌 "가능성"은 단정하지 말고 확인 방법을 함께 제시한다.

용어가 흐리거나 한 단어가 여러 뜻으로 쓰이면 정확한 용어를 제안한다. 저장소가 있고 `domain-modeling` 스킬을 쓸 수 있으면 Skill 도구로 호출해 `GLOSSARY.md`와 ADR 갱신을 맡긴다.

## 4. 끝나는 조건

프런티어가 비면 끝난다. 모든 갈래를 방문했고, 말없이 가정한 것이 남지 않은 상태다. 정리본을 보여 주고 "이대로 공유된 이해에 도달했다"는 사용자의 확인을 받기 전에는 기록하거나 구현하지 않는다.

## 5. 기록한다

**저장소가 있으면** `docs/intent.md`를 만들거나 갱신한다. 기존 내용을 덮어쓰지 말고, 바뀐 항목에는 변경 이유와 날짜를 남긴다. 그리고 `CLAUDE.md`(없으면 `AGENTS.md`)에 이 문서를 가리키는 한 줄 포인터를 넣는다. 둘 다 없으면 어느 쪽을 만들지 사용자에게 묻는다.

**저장소가 없으면** 같은 형식을 대화에 출력한다.

```md
# Intent: <프로젝트/기능 이름>

갱신: YYYY-MM-DD

## 대상과 문제
- ...

## 목표
- ...

## 하지 않을 일
- ...

## 판단 우선순위
1. ...
2. ...

## 위임 경계
- AI가 진행: ...
- 사람이 결정: ...
- 항상 사람이 실행: 운영 배포, 실제 발송, 운영 DB 쓰기, 원격 push, 삭제

## 성공의 모습
- ...

## 미확정 (사람의 확인 필요)
- (미확정) ...

## 강제 장치
- 문서 규칙: <이 문서와 CLAUDE.md에 적힌 것>
- 실제 강제: <CI, hooks, 보호 브랜치 등. 없으면 "없음"이라고 쓴다>

## 변경 이력
- YYYY-MM-DD: <무엇을 왜 바꿨나>
```

마지막에 "강제 장치"가 비어 있으면 한 줄로 알린다. 예: "현재 이 규칙들을 실제로 강제하는 장치가 없습니다. 위험한 git 명령 차단은 `/git-guardrails-claude-code`, 커밋 전 검사는 `/setup-pre-commit`으로 붙일 수 있습니다."

## 다음 단계

사용자에게 다음 흐름을 안내한다. 이 스킬에서 직접 호출하지 않는다.

- 작업 하나를 맡기려면 `/delegate-task`
- 여러 세션에 걸친 큰 기능이면 mattpocock의 `/to-spec` → `/to-tickets` (각 티켓의 Acceptance criteria는 `judgment-gates`의 관찰 가능한 문장 규칙을 따르게 한다)
